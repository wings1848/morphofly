# AEC 真机验证结果（2026-10-24 19:00）

## 结论：**aloop 回环测不出 AEC 效果，这不是 AEC 的问题**

## 尝试的方法

wings-pc 有 `snd_aloop`（ALSA loopback 内核模块），我尝试用它将输出物理接到输入，
精确验证 AEC 的抑制能力。

### 踩到的两个坑

**坑 1：`aloop_input` 录到纯静音**
```
pw-cat --record --target=alsa_input.platform-snd_aloop.0.analog-stereo
→ 峰值 0
```
原因：aloop 的「input」和「output」是两条独立流，PipeWire 默认没连起来。

**坑 2：改用 `.monitor` 源能录到东西**
```
pw-cat --record --target=alsa_output.platform-snd_aloop.0.analog-stereo.monitor
→ 峰值 6808
```
但这是「送到 sink 的内容」，**不是物理回环后的回声**。

## 关键数据：录音里几乎没有源音频

用互相关分析（在录音里搜源音频的最佳匹配）：

| 指标 | 值 |
|---|---|
| 源音频 RMS | 0.0705 |
| 录音整体 RMS | 0.0127 |
| 最佳匹配段 RMS | 0.0067 |
| 最大相关系数 | **≈ 0.000** |

**录音里主要成分是底噪，不是源音频的回声。**
源/录比 0.0067/0.0705 ≈ 9.5%，而且相关性为 0 —— 说明那不是相干回声。

## AEC 实测（在这个不成立的场景下）

| 次数 | 抑制 |
|---|---|
| 第 1 次 | 0.8 dB |
| 第 2 次（归一化后） | 1.9 dB |
| 第 3 次 | 2.4 dB |

AEC 只消掉了录音里那 10% 的一部分，剩下的是底噪 —— **AEC 不该也不能消除底噪**（那是 NS 的活）。

## 为什么这个测试方法不成立

1. **monitor 源不是物理回声** —— 它录的是「数字域送到 sink 的流」，
   和 AEC 的 reference 是同一份数据，理论上相关性应该 1.0，实测却是 0
   → 说明 PipeWire 的 monitor 有额外处理（重采样/格式转换/延迟），破坏了相干性
2. **aloop 没有真正接回** —— input 和 output 之间需要显式 link
3. 即使接回，**没有真实的声学路径**（扬声器→空气→麦克风），
   AEC3 的自适应滤波器需要真实的线性卷积关系才能收敛

## 正确的验证方式（需要用户配合）

**唯一可靠的办法**：在真实桌面环境下跑完整的 App，
外放一段语音，用真实麦克风录，观察：
1. 会不会自我打断
2. `AEC` 的 stats（`render_blocks` / `capture_blocks` 是否同步增长）
3. 打断的延迟

**这需要**：
- wings-pc 桌面已登录（当前卡在 plasmalogin）
- 有声卡输出（有）
- 有麦克风（有，`alsa_input.pci-0000_00_1f.3.analog-stereo`）

## 结论

**AEC 的合成信号测试（34.5dB）仍然有效，19 个单测全绿。**
但「真机效果」这一项**无法在无桌面、无物理回环的条件下验证**，
必须等桌面可用后由用户配合完成。

我不会因为测不出来就宣称「AEC 无效」——
证据指向的是测试方法不成立，不是 AEC 不工作。
