# 硬件事实（2026-10-24 实测）

## wings-pc：没有麦克风 ⚠️

**这是本轮的关键发现，解释了为什么 AEC 在 wings-pc 上测不出来。**

`/proc/asound/cards` 只有两张声卡：
```
0 [Loopback ]: Loopback  — snd_aloop 虚拟回环
1 [PCH      ]: HDA-Intel — 主板音频（只有输出）
2 [NVidia   ]: HDA-Intel — 显卡 HDMI 音频（只有输出）
```

`/dev/snd/` 只有 `pcmC0D0c`（aloop 的录音口）、`pcmC1D0p`（PCH 播放口）等，
**没有真实的 capture 设备**。

## 实测证据

在 wings-pc 上播放 4 秒测试音，同时用「默认输入设备」录音：

| 指标 | 值 |
|---|---|
| 底噪 RMS | 0.00554 |
| 录音 RMS | 0.00797 |
| 比值 | **1.44** |

比值 1.44 意味着录音基本就是底噪 + 一点点串扰，
**扬声器的声音没有被任何麦克风收到**（因为根本没有麦克风）。

## 这意味着什么

1. **AEC 无法在 wings-pc 上验证** —— 没有真实声学路径
2. **snd_aloop 也测不了** —— 数字域回环没有真实卷积关系
   （我试过，源/录相关性 ≈ 0.000，只剩底噪）
3. **wings-pc 的音频测试永远只能测「播放侧」**

## 能测 AEC 的设备

| 设备 | 有麦克风 | 能测 AEC |
|---|---|---|
| wings-pc | ❌ | ❌ |
| wings-gpd（掌机）| ✅ 内置麦克风 | ✅ **是唯一选择** |
| wings-tx-us1（本机云主机）| ❌ 无音频 | ❌ |

## 所以

**AEC 的真机验证必须等 wings-gpd 上线。**

这不是「懒得测」，是物理限制。在 wings-pc 上无论怎么试都测不出来，
我已经花了时间用 aloop、monitor、测试音三种方法验证过，都失败了 ——
失败的根因是硬件，不是方法。

## 顺便纠正一个之前的说法

我之前在 `docs/v2/aec-real-test-result.md` 里说「aloop 的 monitor 源
破坏了相干性」——**这个归因不完整**。

真正的原因是：**wings-pc 根本没有麦克风**，
monitor 源录的是数字域数据，和 AEC 的 reference 是同一份，
理应相关性 1.0，但实测 0 —— 说明 PipeWire monitor 确实有处理。
不过这不是重点，重点是**没有真实声学路径这件事本身**。

## 对测试策略的影响

- **单元测试**：本机跑（229 passed，含 19 个 AEC 测试）
- **语音链路 e2e**：本机跑（真实云端，8/15）
- **播放侧/GUI**：wings-pc 跑（有桌面时）
- **AEC 真机 / 麦克风相关**：**只能 wings-gpd**
