# 「小蝶帮我」漏检问题（2026-10-24）

## 实测数据

| 用例 | 文本 | blanks=4 | blanks=5 |
|---|---|---|---|
| wake-01 | 小蝶 | ✅ 1 | ✅ 1 |
| **edge-02** | **小蝶帮我** | **❌ 0** | **❌ 0** |
| wake-03 | 小蝶儿真好看 | ✅ 0（正确）| ✅ 0 |
| wake-04 | 蝴蝶飞走了 | ✅ 0（正确）| ✅ 0 |

## 为什么不能降 num_trailing_blanks

试了 2 和 3，**直接报错**：

```rust
// core/src/kws.rs:86
anyhow::ensure!(
    self.num_trailing_blanks >= 4,
    "num_trailing_blanks 必须 ≥4，否则「小蝶儿」会误唤醒"
);
```

有硬性断言保护 —— 这是当初实测出来的：
`num_trailing_blanks=4` 就是为了挡住「小蝶儿」（谐音陷阱）。

**降它 = 谐音误唤醒回来 = 更糟。**

## 真正的解法：加唤醒词变体

```txt
x iǎo d ié @小蝶
x iǎo d ié b āng @小蝶帮我     ← 新增
```

这样：
- 用户说「小蝶，在吗」→ 命中「小蝶」
- 用户说「小蝶帮我」→ 命中「小蝶帮我」

不冲突，且不降低安全性。

## 但需要 text2token 工具

```bash
sherpa-onnx-cli text2token \
  --tokens tokens.txt --tokens-type ppinyin \
  --text "小蝶帮我" output.txt
```

本机**没装 sherpa-onnx-cli**，装它是另一个依赖。

## 成本收益判断

| 方案 | 成本 | 收益 |
|---|---|---|
| 装 sherpa-onnx-cli + 加变体 | 0.5 天 | 覆盖「小蝶帮我」这类紧连说法 |
| 接受现状 + 提示用户「喊完稍停」 | 0 | 12/13 已够用 |

## 我的判断：**先不改**

理由：
1. 用户通常会说「小蝶」+ 稍作停顿 + 任务，这是最自然的说话方式
2. 13/14 的通过率在真实场景够用
3. 加变体有风险：变体越多，误唤醒概率越高
4. 当前最缺的是 **AEC 真机验证**，不是这个

**记录为已知限制，排到后面。**
如果用户实际使用中频繁遇到，再装工具加变体。
