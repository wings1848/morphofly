# 跨机传文件（wings-gpd 常离线）

## 问题

`wings-gpd` 是掌机，**经常几小时不联网**。
你在会话窗口里等它上线是浪费——等到了会话可能已经结束。

## 做法：后台挂着，上线自动传

```bash
# 后台启动，最多等 12 小时
nohup tools/gpd_wait_and_send.sh --hours 12 > /tmp/gpd-wait.log 2>&1 &

# 看进度
cat /tmp/gpd-wait.log
```

**上线后它会自动**：
1. `mkdir -p ~/Downloads`
2. `scp` 传文件
3. 校验 sha256（远端没 sha256sum 就退化成比大小）
4. `chmod +x`
5. **发 TG 通知你**（不用你回来看会话）

## 为什么这样设计

| 备选 | 问题 |
|---|---|
| 会话里轮询等 | 会话结束就断了，而且浪费 context |
| 起 HTTP 服务让 gpd 主动拉 | gpd 得先知道地址，不如直接推 |
| 手动等它上线再说 | 你会忘 |

**推送比拉取可靠**：文件在我们手上，gpd 一上线就推，不需要它配合。

## 脚本参数

```bash
tools/gpd_wait_and_send.sh [选项]

  --file <路径>        要传的文件（默认 AppImage）
  --hours <数字>       最多等几小时（默认 12）
  --interval <秒>      探测间隔（默认 60）
  --remote-dir <目录>  远端落点（默认 ~/Downloads）
```

退出码：`0` 成功，`2` 超时，`1` 其他错误。

## SSH 目标解析

`tools/gpd_ssh.sh` 与 `tools/pc_ssh.sh` 同一套兜底策略：

1. `$MORPHOFLY_GPD_SSH` 环境变量（显式覆盖）
2. 主机名 `wings-gpd`（MagicDNS 正常时）
3. Tailscale IP `100.107.9.102`
4. 局域网 IP `192.168.31.10`

**注意**：本机 `/etc/resolv.conf` 被 dhcpcd 覆写过，MagicDNS 经常失效，
所以第 3/4 步的 IP 兜底是必须的。

## 备用通道：HTTP 下载服务

如果 gpd 能上网但 SSH 不通（比如没开 sshd），用这个：

```bash
cd ~/Code_Project/diemeng/dist
python3 -m http.server 5050 --bind 0.0.0.0
# 然后在 gpd 上访问 http://100.99.51.5:5050/
```

**端口选择**：按 AGENTS.md 约定，本机自建服务统一用 5000–6000 段。
5000 已被占用（DSH Web GUI），所以用 5050。

**用完记得关**：
```bash
pkill -f "http.server 5050"
```

## 踩过的坑

1. **`hostname` 解析不到** —— 本机 dhcpcd 覆写 resolv.conf，必须 IP 兜底
2. **`scp` 静默失败** —— 加 `-o BatchMode=yes`，别让它卡在密码提示
3. **sha256sum 可能不存在** —— 掌机精简系统常见，退化成比文件大小
4. **文件权限** —— 传完必须 `chmod +x`，否则 gpd 上跑不了

# AppImage 跨机器崩溃（SIGILL）—— 2026-10-24 踩坑记录

## 症状

在 wings-pc 上打好的 AppImage，拿到 wings-gpd 上跑：
```
Illegal instruction (core dumped)
```

`coredumpctl` 显示 `SIGILL / ILL_ILLOPN`。

## 根因：AppImage 把编译机的系统库一起打包了

Tauri 的 AppImage bundler 是「全自包含」的：它会把**系统里的依赖库**复制进包里。
wings-pc 是 CachyOS，它的系统库（OpenSSL、glib 等）**按 x86-64-v3 编译，含 AVX 指令**。

wings-gpd 的 CPU 是 **Intel Pentium Silver N6000（Jasper Lake）**，只有 SSE4.2，**没有 AVX**。
→ 加载那些库时立刻 SIGILL。

崩溃栈证据（逐步暴露）：
```
#0  libcrypto.so.3 + 0x1feea0     ← 第一次
#0  libglib-2.0.so.0 + 0x50286    ← 换掉 libcrypto 后
```

实测包内 `libcrypto.so.3` 有 **3445 条 `vmovdqu` + 1386 条 `vaesenc`**（AVX/AES-NI），
而 gpd 系统自带的 `libcrypto.so.3` 一条都没有。

## 三次无效的尝试

| 尝试 | 结果 |
|---|---|
| 设 `target-cpu=x86-64-v2` 重编译 | ❌ 只影响**我们的**代码，不影响打包的系统库 |
| 删包内 `libcrypto.so.3` 换系统库软链 | ❌ AppRun 用 `LD_LIBRARY_PATH` 优先加载包内库 |
| 换掉 libcrypto | ❌ 下一个崩在 libglib |

## 正确解法

### 方案 A：在目标机器上编译（推荐）

```bash
# 在目标机上
git clone ... && cd morphofly/app
cargo install tauri-cli --version "^2" --locked
cargo tauri build
```

产物天然匹配本机 CPU 和系统库。

### 方案 B：用 deb 而不是 AppImage（✅ 已在 gpd 实测通过）

deb 只打包我们的二进制，依赖系统库（`libwebkit2gtk-4.1-0` 等），
所以不会带进编译机的 OpenSSL/glib。

```bash
sudo dpkg -i 蝶梦_0.1.0_amd64.deb
```

**实测验证（wings-gpd，2026-10-24 16:18）**：

```bash
# 不用 sudo 也能验证内容
ar x morphofly.deb && tar -xf data.tar.gz
find . -name "*.so*" | wc -l     # → 0，一个系统库都没打
./usr/bin/morphofly-app          # → 启动成功
```

```
INFO morphofly_app: 蝶梦启动 provider=stepfun model=step-1o-audio
INFO morphofly_app: 随包资源目录 dir=.../usr/lib/蝶梦/resources
INFO morphofly_app: 唤醒词常驻监听已启动
INFO morphofly_core::kws: KWS 模型三件套已配对 ...
INFO morphofly_core::kws: KWS 常驻监听已启动
ERROR morphofly_core::kws: KWS 监听线程异常退出 error=KWS 需要麦克风
```

**SIGILL 完全消失，进程存活，窗口创建，唤醒词模型加载成功。**
最后的「需要麦克风」是因为通过 SSH 会话启动，没拿到音频设备权限——
用户正常登录桌面后启动不会有这个问题。

Arch 系（CachyOS）没有 `dpkg-deb`，用 `ar x` + `tar -xf data.tar.*` 解包即可。

**这是本项目推荐的分发方式。**

### 为什么 AppImage 在别的机器可能崩

AppImage 打的是编译机的系统库。实测包内库的 AVX 使用量：

| 库 | 系统版本 | AppImage 包内 |
|---|---|---|
| `libglib-2.0.so.0` | **0 条 AVX** | **1858 条 AVX** |
| `libcrypto.so.3` | 0 | 3445 条 `vmovdqu` + 1386 条 `vaesenc` |

移走包内 140 个含 AVX 的库后，SIGILL 立刻消失——
这直接证明崩溃 100% 来自打包的系统库，和我们的代码无关。

### 方案 C：CI 构建（最可复现）

GitHub Actions 用 `ubuntu-22.04` 构建，系统库是 glibc 2.35 基线，
OpenSSL 也是通用版本。产物比本机打的小（126MB → 应该更小），兼容性更好。

见 `.github/workflows/release.yml`。

## 教训

1. **`target-cpu` 只管你自己的代码**，管不了第三方预编译库和打包进来的系统库
2. **AppImage 「自包含」是双刃剑**：不挑依赖版本，但把编译机的 CPU 优化也带过去了
3. **崩溃栈要一层层剥**：换掉一层会暴露下一层，看似「修不好」，其实是多个库都有问题
4. **跨机器分发的第一选择是 deb**，AppImage 只在「保证同架构同基线」时用

## 检查方法（以后打包前跑一遍）

```bash
# 看包内所有库有没有 AVX
cd squashfs-root/usr/lib
for lib in *.so*; do
  N=$(objdump -d "$lib" 2>/dev/null | grep -c '%ymm')
  [ "$N" -gt 0 ] && echo "$lib: $N 条 AVX"
done
```

或者更简单：**在目标机器上编译**。
