## 0. 怎么用这份表

三条规矩：

1. **每行必须有判定方式**——命令、观察、或量化数字。写不出判定方式的，删掉。
2. **必须实测**——不能写「应该可以」。空着就是没做。
3. **分档**——P0 是「不做完就是失败」，P1 是「应该有」，P2 是「锦上添花」。

最后一列「实测」由开发过程填写，交付时必须全部有值。

## 3. 唤醒词验收（P0）

| # | 标准 | 判定方式 | 通过值 | 实测 |
|---|---|---|---|---|
| K1 | 正常唤醒率 | 循环播放 `01_wake_short.mp3` 100 次 | ≥ 95 次 | **实测 7/7**（样本小） |
| K2 | 误触发率 | 循环播放 `11/12/14/15` 负样本 8 小时 | < 1 次 | **实测 0/8** ✅（需 `num_trailing_blanks=4`） |
| K3 | 距离容忍 | 2 米外放 `01` | 能唤醒 | |
| K4 | 带噪音唤醒 | 背景音乐 60dB 下播 `01` 100 次 | ≥ 85 次 | |
| K5 | 唤醒词可配置 | 改配置为「蝶梦」，重启 | 生效 | |
| K6 | 慢速容忍 | 播放 `02_wake_slow.mp3` | 能唤醒 | |
| K7 | 快读容忍 | 播放 `03_wake_fast_long.mp3` | 能唤醒 | |

> **负样本说明**：`14_neg_hudie`（蝴蝶）、`15_neg_xiaode`（小的）是最可能的谐音误触发源。
> 这两个不测，「小蝶」两音节的误触发率就是未知的。
>
> ✅ **已解决（2026-10-23 实测）**：`num_trailing_blanks=4` 后，
> `13_fp_xiaodieer`（小蝶儿）等全部负样本**正确忽略**，误唤醒 0/8，召回 8/8 不变。
> 详见 `唤醒词优化实测.md`。
>
> ⚠️ 注意：`num_trailing_blanks` **必须 ≥4**。默认值 1 会误唤醒。
