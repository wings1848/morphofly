## 延迟（最重要）

| 场景 | 实测 | 复现命令 |
|---|---|---|
| **纯对话（说完→听见）** | **802ms** | `cargo run -p morphofly-core --features kws --example duplex_fast -- --rounds 6` |
| 多轮对话第 1 轮 | 1077ms | `cargo run -p morphofly-core --example multiturn_test` |
| 多轮对话第 2 轮（含工具调用） | 1652ms | 同上 |
| WS 连接建立 | 126–179ms | 看任意 example 的日志 |

### 延迟是怎么压下来的

| 阶段 | 做法 | 端到端 |
|---|---|---|
| 初始 | `stepaudio-3-realtime-preview` + 服务端 VAD | 5082ms |
| 第二步 | 换 `step-1o-audio` + 服务端 VAD | 1994ms |
| **最终** | `step-1o-audio` + **本地 VAD + 手动 commit** | **802ms** |

**关键**：StepFun 服务端 VAD 的「确认说完」固定 1.95 秒，参数完全无效
（试过 6 个模型 × 4 档参数，差异 <5ms）。所以不用它，改本地判定。

### V3 真机增补（2026-10-25，gpd）

- **本地反应**（VAD 判定人声 → 停播）<10ms：日志里 `本地判定开口` 与
  `⚡ 打断：停播 + 取消当前回复` 落在同一帧。
- 真机抓到一次完整打断：`interruptions: 1` + 状态回到 S2
  （之前 58 次会话全是 0，这条能力此前从未被真机验证过）。
- 注：注入式测试的「注入音 → 判定」耗时约 2.4s，那是虚拟音源链路延迟
  （paplay 启动 + null-sink/monitor + 采集缓冲），**不是产品反应时间**。
- 复现：`tools/verify_bargein.sh`；限制见 `docs/v2/bargein.md`。

## 已知弱点

### 1. 英文项目名对中文 ASR 不友好

| 说的 | ASR 听到 |
|---|---|
| diemeng | daimian / diamond / aimeng（3/3 全错） |
| 蝶梦 | 100% 正确 |

**建议**：对用户一律说中文名「蝶梦」，英文只在代码里用。

### 2. 内存 488MB（见上）

### 3. 打断参数偏激进

`min_speech_duration=0.08` 是为了达到 300ms。
嘈杂环境（背景音乐、电视）可能需要退回 0.12s 避免误打断。
