
## 三个必须知道的坑（都是实测踩的）

### 1. `num_trailing_blanks` 必须 ≥ 4

`KeywordSpotterConfig::default()` 里是 **1**。
设成 1 时「小蝶儿」会误唤醒；设成 4 后误唤醒 0/8，召回不变。

代码里 `KwsConfig::validate()` 会硬性拦截 `< 4`。

### 2. 模型包里有两套模型，必须配套使用

`sherpa-onnx-kws-zipformer-zh-en-3M` 目录里有 8 个 onnx：
- `chunk-16` 和 `chunk-8` 两套
- 每套的 encoder/joiner 有 int8 和全精度，**decoder 只有全精度**

随手挑会配成「chunk-16 encoder + chunk-8 decoder」→ 输出是垃圾 → **每帧都命中**。

`pick_model_set()` 会先定档位（优先 chunk-16）再挑三件套，并自检文件名一致性。

### 3. 绑定层 `get_result` 没命中时返回 `Some(空)` 而不是 `None`

这是最隐蔽的：sherpa-onnx 2.0.0 的 **Rust 绑定**在没命中时返回
`Some(KeywordResult { keyword: "", json: "{\"keyword\": \"\", ...}" })`，
而 **Python 侧**返回 `None`。

所以 Rust 侧必须额外判 `keyword` 非空（`is_real_hit()`），
否则**纯静音音频都会"命中"**。有回归测试 `empty_keyword_is_not_a_hit` 锁死。

## 架构

```rust
use diemeng_core::kws::{KwsConfig, WakeListener};

let cfg = KwsConfig::default();   // ~/.diemeng/kws-model + ~/.diemeng/keywords.txt
let listener = WakeListener::start(cfg, |ev| {
    // ev 是 WakeEvent::Detected { keyword }
    // 生产路径：状态机 S0 --WakeWord--> S1
})?;
// ...
listener.stop();
```

- `WakeListener` 跑独立线程，阻塞读麦克风，**不占 tokio runtime**
- 只在 S0 时触发（`wake_stimulus_for()`），避免通话中重复唤醒
- 本地处理，**不联网、不上传音频**
