### 1.3 Wails v3 麦克风权限（官方文档实测）

来源：<https://v3.wails.io/features/windows/permissions/>

平台支持矩阵：

| 能力 | Linux | Windows | macOS |
|---|---|---|---|
| 麦克风 | ✅ | ✅ | ✅ (macOS 12+) |
| 摄像头 | ✅ | ✅ | ✅ |
| 定位 | ❌ | ✅ | ❌ |
| 通知 | ❌ | ✅ | ❌ |

关键细节：
- Linux (WebKitGTK) 默认允许麦克风；**在这个特性之前 `getUserMedia` 一直返回 `NotAllowedError`**
- Windows (WebView2)：**一旦设置了 Permissions 映射，没列出的能力会弹原生框**，必须显式列全
- macOS：`Info.plist` 必须加 `NSMicrophoneUsageDescription`，否则可能直接崩溃；TCC 仍会独立询问

| 中途打断 | 停止延迟 **71ms** | — |
| 工具调用 | 0.596s 发起，0.682s 续答 | 4.046s |

**价格**（四档）：

| 类型 | 单价 |
|---|---|
| 音频输入 | ¥6 / 百万 token |
| 文本/图片/视频输入 | ¥1.5 / 百万 token |
| 文本输出 | ¥4.5 / 百万 token |
| 音频输出 | ¥12 / 百万 token |

**官方明说的三个坑**（原文摘录）：
1. 「如果业务要求 500 毫秒以内，需要在端上做流式采集和播放缓冲」
2. 「VAD 模式对合成音频不友好。TTS 生成的音频结尾没有自然停顿，服务端检测不到『说完』，会一直等」
   > ⚠️ **这条不适用于 edge-tts**：本机实测 edge-tts 音频有 0.56–1.39s 尾部静音（见下节更正）
3. 「输出模态决定事件名。只开文本时收 `response.text.delta`，带音频时收 `response.audio_transcript.delta`」

### 1.5 Gemini Live 价格（官方定价页实测）

来源：<https://ai.google.dev/gemini-api/docs/pricing?hl=zh-cn>（更新 2026-10-22）

Gemini 3.8 Live / 3.1 Flash Live：

| 类型 | 价格 |
|---|---|
| 音频输入 | $3.00/M（或 $0.005/分钟） |
| 音频输出 | $12.00/M（或 $0.018/分钟） |
| 文本输入 | $0.75/M |
| 文本输出 | $4.50/M |

**⚠️ 此处原计算有误，已更正（2026-10-23）**

原写法「$0.005 + $0.018 = $0.023/分钟」错把**两个单价直接相加**——
这两个分别是「输入音频每分钟」和「输出音频每分钟」的价，不能相加。

正确算法（假设 1 小时里用户说 30 分钟、AI 说 30 分钟）：

```
输入：30 分钟 × $0.005 = $0.150
输出：30 分钟 × $0.018 = $0.540
合计：$0.690/小时 ≈ ¥4.97/小时
```

**而且 Qwen 也不能按 ¥0.6 算**——它每轮会把历史对话重新作为输入计费。
Qwen 真实成本（150 轮、音频历史 600 秒截断）≈ **¥3.8/小时**。

**真实价差：¥4.97 vs ¥3.8，只有约 1.3 倍。**

选 Qwen 的真正理由不是「便宜 16 倍」，而是：
1. 便宜（约 1.3 倍，聊短对话时优势更大）
2. **中国大陆直连**（Gemini 官方可用地区列表不含中国大陆，这是决定性的）
3. 中文能力
4. 工具调用完整

**对我们的价值**：
- ✅ 借鉴美学：暗色、克制、极简、动画细腻、陪伴感
- ✅ 借鉴分发：一个安装包，装完就用
- ❌ 不借鉴：Live2D 虚拟角色（我们要小球）、歌词同步（与语音无关）

## 3. 既有资产复用清单

### 3.1 `想法/语音交互前台架构.canvas`（31 节点）

**这是本项目最重要的前置资料。** 里面有 StepAudio 的**真机实测数据**：

| 指标 | 实测值 |
|---|---|
| 连接建立 | 144 ms |
| 函数调用触发 | 1499 ms |

**已实测跑通的协议细节**：
- 端点 `wss://api.stepfun.com/v1/realtime`
- 模型 `stepaudio-3-realtime-preview`
- 鉴权：握手头 `Authorization: Bearer $STEPFUN_API_KEY`

**文档里没有、只能抓包才知道的三条**：
1. `response.function_call_arguments.*` 事件
2. 文本要读 `response.audio_transcript.delta`（**不是** `response.text.delta`）
3. `function_call_output` 回灌后模型会继续说话

**已经设计好的 4 个工具**：`delegate_task` / `query_progress` / `cancel_task` / `append_requirement`
**已经想清楚的架构约束**：进程边界 + 工具白名单 + `toolFilter` + instructions 四道锁

> 这份画布的结论直接沿用了，不用重新推导。

### 3.2 DSH 内置语音包

| 包 | 作用 |
|---|---|
| `dsh-experimental-voice-input-bundle` | 组合包：语音服务 + 本地 SenseVoice + 浏览器麦克风 |
| `dsh-experimental-speech-to-text-sensevoice` | 本地 CPU 跑 SenseVoiceSmall ONNX + Silero VAD，**不需要 Python** |
| `dsh-experimental-api-speech-to-text` | 加过权的中转 Remote，限制 `maxAudioBytes` / `maxDurationSeconds` |
| `dsh-experimental-client-ui-voice-input` | 浏览器麦克风按钮，录音→转写→插入草稿 |

**能省的事**：不用从零做 ASR 链路。V1 可以先复用 SenseVoice，只补「实时双工 + 唤醒 + 小球」。

**注意**：这些是 **experimental** 包，API 可能变；且它们做的是「录一段→转文字」，不是「实时双工对话」，不能直接当实时语音用。

### 3.3 DSH 接入方式（已确认）

| 方式 | 命令 | 用途 |
|---|---|---|
| ACP | `dsh --profile acp` | 标准 ACP v1，stdio JSON-RPC，自动化客户端首选 |
| SDK | `dsh --profile sdk` | JSON-RPC stdio |
| Web | `dsh web` | 浏览器 GUI |

ACP 标准流程（来自官方 README）：
> initialize → create session（绝对 cwd + 可选 MCP 声明）→ 选 model 或 reasoning_effort → prompt 并观察语义更新 → `session/close`

还支持 `session/list` / `session/resume` 跨进程恢复。

## 6. 本次调研的方法与局限

**做了什么**
- 官方文档逐页 fetch 并摘录原文数字
- 关键价格/模型名标注了来源 URL 与日期
- edge-tts、sherpa-onnx 绑定、Wails 权限、yachiyo 下载接口都做了**实际调用验证**

**没做什么**
- 没有真实调用任何实时语音 API（无 API Key）
- 没有下载 sherpa-onnx KWS 模型实测唤醒率
- 没有构建 Wails 项目测体积
- 没有验证豆包（文档需登录 + JS 渲染）

**结论的置信度分级**
| 结论 | 置信度 | 依据 |
|---|---|---|
| Qwen 首音频 1.37s | **中高** | 阿里官方博客实测，非我实测 |
| sherpa-onnx 支持 Go/Rust | **高** | 官方 README 绑定表 |
| ~~sherpa-onnx 支持 ESP32~~ | **❌ 错** | **2026-10-23 更正**：官方平台表无任何 MCU，全仓搜 esp32 只 1 个无关 issue。ESP32 必须用 esp-sr WakeNet |
| ~~Qwen 比 Gemini 便宜一个数量级~~ | **❌ 错** | **2026-10-23 更正**：漏算上下文累积 + Gemini 单价算错，实际只差约 1.3 倍 |
| ~~Wails v3 三平台麦克风可用~~ | **❌ 已废弃** | 方案改为 Tauri + 原生音频，音频不走 WebView |
