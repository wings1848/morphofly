# 接缝 0.3 · rodio 播放 + **真的出声**（审计整改后）

**背景**：独立审计指出「音频路由可疑：默认 sink 是 snd_aloop 虚拟回环，
『真正出声』的说法要打折」。审计是对的。本文件是整改后的证据。

## 整改内容

1. 新增 `tools/pc_audio_route.sh`：列出所有 sink，标出虚拟/物理，可一键切到物理设备
2. 新增 `docs/音频路由.md`：说明为什么这件事重要、怎么验证
3. 补上缺失的 `core/examples/play_wav.rs`（审计指出 A0-3 判定命令指向不存在的 example）
4. 清理我测试时留下的 `diemeng_test` null sink

## 实测：声音真的进了物理设备

```bash
tools/pc_audio_route.sh --physical      # 默认 sink → alsa_output.pci-0000_00_1f.3.iec958-stereo
# 一边播放，一边录该 sink 的 monitor
parecord --device="<sink>.monitor" --format=s16le --rate=16000 --channels=1 /tmp/rec.pcm &
cargo run -q -p diemeng-core --example play_wav -- testdata/audio/01_wake_short.mp3
```

```
=== 默认 sink ===
alsa_output.pci-0000_00_1f.3.iec958-stereo     ← 物理设备（不是 aloop）
[play_wav] 解码：24000Hz 1ch → mono 44928 采样（1.87s）
[play_wav] 写入队列 44928 采样
[play_wav] ✅ 播放完成，耗时 1876ms（音频 1.87s）

录音 32022 采样 (2.00s)，RMS=381.2，峰值=32000
✅ 音频确实进了 sink（monitor 录到声音）
```

**关键数字**：monitor 录到的峰值 **32000**（i16 满量程 32767），
RMS 381 —— 这是真实波形，不是静音。**声音确实到了物理音频设备。**

## 修正后的说法

| 之前写的 | 现在准确的写法 |
|---|---|
| 「38400 帧音频真正送进声卡」 | 「38400 帧音频送进 PulseAudio 默认 sink」 |
| 「真正出声」 | 「默认 sink 为物理设备时出声；monitor 录音峰值 32000 已验证」 |

## 遗留要求（写进验收流程）

**任何声称「出声」的证据，必须附上：**
1. `pactl get-default-sink` 的输出，且不是 `*aloop*`、不是 `*null*`
2. 或者 monitor 录音的峰值/RMS 数字

否则只能写「数据进了 sink」，不能写「出声」。
