## 踩了三个坑（每个都值得记）

### 坑 1：模型包里有 8 个 onnx，随手挑会配错

模型目录里有两套：`chunk-16` 和 `chunk-8`，各自 int8 / 全精度。
按「前缀 + 优先非 int8」随手挑，会挑出 **chunk-16 的 encoder 配 chunk-8 的 decoder**
→ 模型不匹配 → 输出是垃圾 → **每一帧都"命中"**。

修法：先定档位（优先 chunk-16），三件套必须同属一套。
自检判据是「去掉 `.int8` 后文件名一致」——因为 **decoder 根本没有 int8 版**
（只有 encoder/joiner 有），不能要求三件套精度一致。

### 坑 2（最隐蔽）：绑定层 `get_result` 没命中时返回 `Some(空)`，不是 `None`

```
step=1 keyword="" tokens="" start=0.00 json="{\"start_time\":0.00, \"keyword\": \"\", ...}"
step=2 keyword="" tokens="" start=0.00 json=...
解码 2 步，get_result 非 None 2 次      ← 喂的是纯静音！
```

Python 侧（`sherpa_onnx` 包）返回 `None`，所以 Python 脚本一切正常。
Rust 侧如果写 `if let Some(r) = get_result(...)` 就当命中，
**纯静音音频都会"命中"** → 这就是第一次跑出「误唤醒 8/8 = 100%」的真凶。

修法：必须判 `keyword` 非空（`is_real_hit`）。加了回归测试
`empty_keyword_is_not_a_hit` 锁死。

### 坑 3：`num_trailing_blanks` 必须 ≥4，且要真的传进去

`KeywordSpotterConfig::default()` 里是 **1**。我们的 `build_config` 显式设成 4，
并且在 `KwsConfig::validate()` 里硬性拦截 `< 4`（报错信息指明参数名）。

## 架构

```rust
// 生产路径
let listener = WakeListener::start(cfg, |ev| {
    // 命中 → 状态机 S0 --WakeWord--> S1
})?;

// 离线验证（不需要麦克风，CI 可用）
let hits = detect_in_file(&cfg, Path::new("test.mp3"))?;
```

- `WakeListener` 跑独立线程，阻塞式读麦克风，不占 tokio runtime
- `wake_stimulus_for(state)` 只在 S0 返回 `Some(Stimulus::WakeWord)`（其他状态忽略重复唤醒）
- feature gate：`--features kws`。**默认不开**——本机（Debian 云主机）缺 libstdc++，
  静态链接失败；wings-pc 完整工具链可以开。
