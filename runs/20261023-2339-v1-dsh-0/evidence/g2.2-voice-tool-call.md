# 阶段 2 · 语音 → 工具调用 → 派活 → 语音确认（真机，最有价值的一条证据）

**命令**（wings-pc）：
```bash
tools/pcrun.sh 'set -a; . ~/.diemeng/credentials; set +a; \
  cargo run -q -p diemeng-core --example voice_task -- --file testdata/audio/16_cmd_delegate_full.mp3'
```

音频内容（edge-tts 生成）：「小蝶，在 diemeng 项目根目录运行 ls，用一句话告诉我有哪些目录」

## 实测时间线

## 这条证据证明了什么

| 能力 | 状态 |
|---|---|
| 语音模型**真的会调用工具**（不是聊天） | ✅ 收到 `ToolCall{name: delegate_task}` |
| 工具参数是结构化 JSON | ✅ `{"dir": ..., "task": ...}` |
| 我们这侧能接住并执行 | ✅ dispatcher 创建任务 002 |
| 结果能回灌给模型 | ✅ `send_function_call_output` |
| 模型能基于结果继续说话 | ✅ 「任务已经派出去了，等结果出来我马上告诉你」 |
| **物理隔离成立**：它只有 4 个函数 | ✅ 没有任何文件/命令工具，它只能「转交」 |

## 一个真实的 ASR 弱点（必须记下来）

「diemeng」被听成 **`/daimian`** —— 英文项目名对中文 ASR 不友好，而且它自作主张补了 `/` 变成绝对路径。

后果：这个任务会去一个不存在的目录执行，必然失败。

**对策（已写进 TODO）**：
1. instructions 里加硬约束：*「路径/项目名不确定时，必须先追问确认，不要自己猜」*
2. `delegate_task` 在 dispatcher 侧加目录存在性校验，不存在就返回「这个目录不存在，是不是想指 X？」让模型复述
3. 长期：支持用户配置「项目别名表」（说「蝶梦项目」→ `~/Code_Project/diemeng`）

## 另一条更早的观测：模型会主动澄清

播放 `07_cmd_fix_bug.mp3`（「小蝶，把登录页的报错修一下」）时，模型**没有**乱派活，而是追问：

```
它说: 你能告诉我登录页的代码在哪个项目里吗？或者直接把项目路径发给我也行。
```

这是**正确行为**——任务描述不自包含（验收 A6），它选择澄清而不是瞎猜。
说明 instructions 里的「task 必须自包含」起了作用。
