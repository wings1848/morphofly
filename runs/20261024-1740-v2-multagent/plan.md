# 实施计划

## Context
V2 要按 canvas 新需求推进：多 agent、AEC、UI/UX、修缺陷。

## Goals
1. 5 个现存缺陷全部修完
2. 多 agent 语音切换（至少可用）
3. AEC 接入且不牺牲打断能力
4. 真机 e2e 通过率 > 80%

## Non-goals
- 完整多 session 进程池
- ESP32 / 安卓 / Web 端
- 内存原生重写（等用户决策）

## Design
按「先修破的，再加新的」顺序：
1. 修缺陷（取消/追加/sessionId/进程池/打断生成）
2. 加 set_context + 别名表
3. AEC（sonora）
4. UI/UX（托盘/贴边/拖动）
5. 真机 e2e 验证

## Alternatives 否掉的
- 先做多端：核心还没稳，多端会放大问题
- 先做内存优化：收益不确定，且用户没拍板

## 不变量（本次必须保持不变）
1. **语音模型物理上无文件/命令能力**（测试：`tools::tests` 黑名单变体）
2. **AEC 不牺牲打断能力**（测试：双讲场景人声保留 >30%）
3. **帧长恒 320 样本**（测试：`aec::tests` 帧长断言）

## Cross-cutting
- 提示词约束不可靠 → 关键行为必须有代码兜底
- 每个「切换类」功能必须有端到端验证，不能只改本地字段
